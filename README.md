# 专利权利要求映射工作台

用于专利代理人与审查人员核对权利要求、技术特征和说明书支持依据的前端工作台。数据按案件本地保存，可恢复上次工作位置。

## 功能

- 录入独立/从属权利要求与说明书段落。
- 将权利要求拆分为技术特征，设置父级层级、特征间引用。
- 为每个特征映射一个或多个说明书支持段落。
- 自动提示引用循环、缺少依据、空特征和“特征已删除但映射未清理”。
- **两侧状态分持**：
  - 代理人一侧：技术特征、层级、引用、支持段落（含版本快照）。
  - 审查员一侧：代理人草稿只读副本、批注、每条特征的审查结论、发件箱与同步日志。
  - 观察者只读；越权操作在服务层直接拒绝，互不覆盖。
- **带回对账（按“特征正文 + 指向段落”指纹）**：
  - 指纹一致：照旧有效。
  - 特征在结论确认之后又被改动（正文或支持段落）：该条审查结论作废并粘住，等审查员按最新副本重新确认；批注原文保留并标注“所指内容已改动”。
  - 指向特征已撤下：先按指纹自动找回唯一同内容特征，找不到或候选不唯一则挂起，由代理人人工挂接或丢弃。
  - 幂等：每条意见版本以 `意见id@确认时间` 为键，带回失败后从审查员一侧重试，已对上的不重复挂；代理人草稿与旧结论全程保留。
- 全量操作撤销重做，使用 `Ctrl/⌘ + Z` 与 `Ctrl/⌘ + Shift + Z`。
- 保存权利要求版本，逐项比较正文差异并恢复历史版本。
- 导出完整 JSON（含两侧状态）或可核对的 CSV（含审查结论列），本地保存上次标签页、特征和滚动位置。

## 技术栈

- Angular 19、TypeScript、RxJS
- PrimeNG 19、PrimeIcons
- 浏览器 `localStorage`

## 本地开发

```bash
npm install
npm start
```

开发服务器监听容器内端口 4200，仅用于本地开发；项目不在源码中定义宿主端口。

## 生产构建

```bash
npm install
npm run build
```

产物位于 `dist/patent-claim-workbench/browser`。

## Docker

```bash
docker build -t sologsb-1005 .
docker run --rm -p 10005:80 sologsb-1005
```

nginx 在容器 80 端口提供构建产物，并按根端口表映射到宿主 `10005`。

## 数据说明

数据与版本存在浏览器本地。若需团队共享或长期归档，请在后续接入后端存储；当前实现为明确的前端离线原型。
